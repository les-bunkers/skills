name: rough
description: Rough cut stage of a video — choose what to keep from the transcript as text anchors, snap them to the words, produce a cut list with retimed captions and colour markers, print every seam, let the human pick the take and the camera of each passage in DaVinci Resolve's Take Selector when the script was recorded several times (teleprompter retakes, multicam studio), and build the rough timeline in Resolve (multicam aware): `<Video> 16x9` on the comp route, the long 9:16 on the NLE route. Use when choosing takes, picking takes or cameras, building a take picker, reading the human's picks, building or rebuilding a rough cut or selects timeline, changing what a cut keeps, reading the seams of a cut list, or when running /videos:rough.
argument-hint: "[video name]"

`videos.py` = `uv run "${CLAUDE_PLUGIN_ROOT}/scripts/videos.py"`. `S` = `${CLAUDE_PLUGIN_ROOT}/scripts`. Work from the record folder (`videos.py show <video>` → `record:`). Anchor format, markers and cut-list fields: [engine](${CLAUDE_PLUGIN_ROOT}/references/engine.md).

## Do

1. Gate: ingest and transcribe `done`. Read the record's brief, decisions and `style:` files, then the whole transcript (`python "$S/words_dump.py" --project cut/edit.json --src A [--src B]`).
2. Decide keep ranges with the brief: the best take of each idea, false starts and retakes out (a line restarted several times after a stumble keeps its last complete attempt), asides and private remarks out, claims to verify flagged. Dead air and breaths go at tighten. Write `cut/rough.json`: `timeline` (the video's plain name, "<title>": no format, stage, version or date in it; the build adds the format), `segments` as `[src, [approx s, "phrase"], [approx s, "phrase"], {options}]` (times as the dump prints them; `*` = any one misheard word; `face: true` on hooks/outros where the program shows a screen but the speaker talks to camera; `alt` = alternate take parked after the end), `markers` (Green = short candidates: moments that stand alone as a short, cut by clips once the 9x16 is approved), `end_note` (what was cut and why).
   Same script recorded several times (teleprompter retakes, several passes of a line): the human chooses, never the agent. Cut the script into passages where a choice makes sense (the intro, each chapter, the outro, a line that matters), each segment = the default take (the project's house rule, else the last recording), with `takes` = the same passage in the other recordings, `[[src, [s, "phrase"], [s, "phrase"]], …]`. Anchor every take on the same words, so any take of one passage joins any take of the next.
3. `python "$S/rough.py" --project cut/edit.json --spec cut/rough.json --check` → fix every failing anchor (the error shows the words near it).
4. `python "$S/rough.py" --project cut/edit.json --spec cut/rough.json --out cut/rough` → `cut/rough.cuts.json` + `cut/rough.srt`. Read EVERY printed seam `…cut before || kept … || cut after…`: a seam that cuts mid-thought or repeats a word is a wrong anchor.
5. Take picker (the default whenever segments have `takes`, or the human wants to choose the camera of each passage). Rules for every call: `/videos:resolve`. `python "$S/resolve_build.py" --project cut/edit.json --cuts cut/rough.cuts.json --mode takes --format <fmt> --dry-run` (`<fmt>` = `16x9` on the comp route, `9x16` on the NLE route) (clips, takes per clip, the default of each), then `--snippet` and run the printed code with `run_script_unsafe`. Result: `ok` true (`takes_per_clip` = `takes_expected`), `format.got` = `<fmt>`, `saved` true. The picker `<title> <fmt> - takes` lands in `01 Timelines/WIP/Processing` = one clip per passage on V1; its takes = every camera of every recording of that passage, as plain camera clips (never multicam clips: Resolve crashes when the human opens Take Selector on them), all as long as the passage's longest take; take 1 = the default. `B.release(resolve, project, "<title> <fmt> - takes")` moves it to `01 Timelines/Waiting for review` (`/videos:resolve`). Tell the human: open the timeline, right-click a clip → Take Selector, pick, and the Blue marker of each passage lists its takes in order. `videos.py set <slug> rough "review <human>: picks in <picker name>" --next "human picks takes and cameras"`, then wait.
   Human done → `--mode read_takes --out cut/picks.json --snippet`, run it (reads which file each clip plays, so it works whichever timeline is current) → `unknown` empty (else a clip was replaced by hand: ask) → `python "$S/rough.py" --project cut/edit.json --spec cut/rough.json --picks cut/picks.json --out cut/rough`: the picked recording becomes each segment's range, `cam` = the picked camera, both written into `rough.json` (the previous one kept as `rough.before-picks.json`; later runs need no `--picks`). Read the seams again: a picked take joins its neighbours on new words.
6. Resolve (rules for every call: `/videos:resolve`): `python "$S/resolve_build.py" --project cut/edit.json --cuts cut/rough.cuts.json --format <fmt> --dry-run` (tracks, counts, first items), then `--snippet` and run the printed code with the Resolve MCP tool `run_script_unsafe`. V1 = multicam or the program file, sound linked; `face` segments = the multicam clip's active angle switched to the face camera, `cam` segments (picks) = their picked camera for the whole passage (tighten keeps it) (the build places the pieces, then switches V1's angles through a .drt round trip; if that fails they stay as clips on V2 / V3 and `angles` in the result says why); subtitles; markers. Check `result`: `len` = `expected`, `subs` > 0, `markers` = count in the cut list, `format.ok` true (9x16: 1080×1920, sources centre-cropped to fill the frame). Then `get_thumbnails` on the timeline across every camera: a face cut by the frame edge or off the crop → Pan per piece (framing: [resolve](${CLAUDE_PLUGIN_ROOT}/references/resolve.md) § Timelines). The build lands in `01 Timelines/WIP/Processing` as `<title> <fmt>` (you are still on it), tagged with the video's name, the format and `rough`. A timeline with the same name exists → `--mode inspect` first (`same_as_cut_list: false` = hand edits → ask), then `--replace`: the existing one is filed in `01 Timelines/WIP/Archive` as `<title> <fmt> vNN <date> rough` (`archived` in the result) and the new build takes the working name. Nothing is deleted. The route sets the format: comp route = `16x9` (the comp picks the camera of each span and makes the 9:16 from the same spans); NLE route = `9x16`, because the 16:9 and the shorts are made from the approved 9x16 (`/videos` § Order).
7. `B.release(resolve, project, "<title> <fmt>")` → `01 Timelines/Waiting for review`, then `videos.py set <slug> rough "review <human>: <timeline name>, markers Yellow = claims to check" --next "human watches the rough"`. Claims, prices and facts to check go in the record's notes.

## Gate

Status `review` = wait (for the picks, then for the rough). The human's notes go under `## Decisions`; rerun steps 2–6 with `--replace` (a new choice of take or camera = rebuild the picker with `--replace`: it offers the current picks as take 1) (the previous rough goes to the archive under its version name; the working timeline keeps its name). `done` only when the human approves the rough (`B.release(…, review=False)` → back to `WIP/Latest`): tighten builds on it.

## Markers

Blue chapters · Green short candidates (cut from the approved vertical by clips) · Yellow claims or facts to check · Red end of the main cut (its note lists what was cut) · Purple alternate takes.
