`videos.py` = `uv run "${CLAUDE_PLUGIN_ROOT}/scripts/videos.py"`. `S` = `${CLAUDE_PLUGIN_ROOT}/scripts`. Work from the record folder (`videos.py show <video>` → `record:`). Resolve rules and failure log: `/videos:resolve` ([resolve](${CLAUDE_PLUGIN_ROOT}/references/resolve.md) § Rendering); engine notes: [engine](${CLAUDE_PLUGIN_ROOT}/references/engine.md) § Resolve.

## Comp route

The finals are the comp renders the human approved at formats (16:9 and 9:16). Per file: frame count = the plan's `end_f`, `comp.py gaps <file>` clean, loudness checked (`uv run "$S/loudness.py" fix <in> <out>` when it is off: −14 LUFS ± 0.5, true peak ≤ −1 dBTP), video CI `--stage master`. File each one: `B.file_export` into `04 Exports/<Video>` when the project lives in Resolve, else next to the record's other finals. Then `videos.py set <slug> master "done <date> 16x9 + 9x16 <paths> <LUFS>/<dBTP>"`, `videos.py set <slug> wide "skip comp route"`, and `/videos:clips` or `/videos:qc`. The steps below are the NLE route.

## Do (NLE route)

1. Gate: formats `done` on a talking-head video (the whole `<Video> 9x16` with its layers; other kinds: tighten or rough `done`) and audio `done` (a mastered track sits on it, `/videos:audio`). The record's `resolve:` names the timeline. The human watches the whole vertical and approves it: this approval is what the 16x9 (`/videos:wide`) and the shorts (`/videos:clips`) are made from. Confirm the render with the human (it occupies the GPU and Resolve for minutes). Freeze what was approved: a copy named `<Video> 9x16 vNN <date> approved` in `01 Timelines/Published` (`B.snapshot(resolve, project, "<Video> 9x16", "approved", to=B.PUBLISHED)`, `/videos:resolve`), and the working timeline back to `WIP/Latest` (`B.release(…, review=False)`); the render still runs on the working timeline.
2. Cuts as they are now, never as planned (the human may have moved some): `python "$S/resolve_build.py" --project cut/edit.json --mode read_cuts --name "<timeline>" --out cut/final.cuts.json --snippet` → run with the Resolve MCP tool `run_script_unsafe`. `unknown` must be empty. In-the-voice joins come back on whole frames.
3. Render: `python "$S/render_finals.py" --timeline "<timeline>" --target-dir "<media folder>/masters" --audio-track MASTER --suffix -master --snippet` → run it. Per timeline it checks that only the audio track named `MASTER…` is enabled (else skipped, with the track list), loads the master preset for its size, sets folder and name, and on a 9x16 timeline the frame size too (a job whose size differs from its timeline is deleted, `skipped` says so), starts. Masters (`scripts/resolve_presets.py` builds each preset once per Resolve, from a stock preset, and reads its bitrate back):
   - 16:9 at 3840×2160 → `videos master 4K HEVC 80M`: MP4, H.265 NVIDIA Main10, VBR 80 Mbps (a talking head averages ~50), AAC 320k. About twice YouTube's 4K recommendation.
   - every other size (the 9x16, the shorts, HD 16:9) → `videos master H264 20M`: MP4, H.264 NVIDIA, VBR 20 Mbps, AAC 320k. A 9:16 crop of 4K holds 1215×2160 real pixels and Reels / TikTok show 1080×1920 at most; 20 Mbps stays under the bitrate caps upload APIs list, so one file serves every platform.
   - No ProRes intermediate: the preset carries the bitrate (the API's `VideoQuality` is ignored, [resolve](${CLAUDE_PLUGIN_ROOT}/references/resolve.md) § Rendering). No NVIDIA encoder → the stock "YouTube - 2160p" / "1080p" preset (~11 Mbps at 4K, too low for a 4K upload), flagged `preset_fallback` in the job report: say so to the human.
   - One file per deliverable. A second, smaller copy only where an upload tool caps the size (a long 16x9 through a scheduler's API), made from the master with ffmpeg.
4. Wait: poll with `run_script` (`project.GetRenderJobStatus(<job id>)`) until `Complete`; ffprobe sees a duration while Resolve still writes. Then `resolve.OpenPage("edit")` (Deliver swallows track toggles).
5. Check the file: `uv run "$S/finals_check.py" "<media folder>/masters/<name>-master.mp4" --cuts cut/final.cuts.json --project cut/edit.json --ref "<mastered track wav>" --json checks/master.json`.
   Pass = video stream present and frames = the timeline's length; −14 LUFS ± 0.5 and true peak ≤ −1.0 dBTP on the encoded file (ebur128; loudnorm reads ~0.3 LU low on a silent tail); content: render = 1.0 × the mastered track at lag 0, or √2 × when a mono master sits on a stereo track (rendered dual mono, +3.01 dB; the check says so); a second track mixed in or a shifted edit fails. `--ref` alone is enough (a hand-edited timeline has no cut list); a run with neither `--ref` nor `--cuts` + `--project` prints `SKIP content`. No mastered track yet → leave out `--ref` and add `--no-loudness`: the render is then compared with the sound rebuilt from the cut list and the sources.
   Two renders that must line up (track A vs track B): `uv run "$S/sync_check.py" a.wav b.wav` → every window lag 0.
6. Video CI on the master: `uv run "${CLAUDE_PLUGIN_ROOT}/scripts/video_ci.py" "<media folder>/masters/<name>-master.mp4" --slug <slug> --stage master` (spec, loudness, black / frozen / silent stretches, face framing, grade, secrets; at most 150 stills per check). RED → fix before anyone sees it.
7. File the checked master in the pool: `B.file_export(resolve, project, "<media folder>/masters/<name>-master.mp4", "<Video> 9x16")` → `04 Exports/<Video>` (`/videos:resolve`). Then `videos.py set <slug> master "done <date> <path> -14.0/-1.9" --next "wide + clips, side by side from the approved 9x16"` (the measured values; refused without fresh, non-red CI). A failed check → `blocked <what failed>` and tell the human.

## Rules

- Graphics live as alpha layers on the timeline by default (`/videos:formats`, [layers](${CLAUDE_PLUGIN_ROOT}/references/layers.md)): render with the layers tracks on and that render is the final of its format. A text-free master (layers tracks off) only when a baked route needs it: captions, hooks and graphics then come in `/videos:formats`, from `cut/final.cuts.json` and the tight SRT.
- Steps 2–6 also render the 16x9 (`/videos:wide`) and each short (`/videos:clips`, `--prefix "<Video> 9x16 S"` queues every short), with their own `--suffix` and CI stage.
- A cut moved after the approval → change it on the 9x16 first: `B.claim`, read the cuts again (step 2), re-render, re-check, approve again; then carry the change to the 16x9 and to the shorts whose range it touches.
- `/videos:qc` is the gate before anything ships.
